## Matched facts and tasks

Seed a proposal from the [pinned cancellation-cleanup source](CANCELLATION_CASE.md), review it with the coordinating implementation agent's explicitly synthetic fixture attestation, and preserve that receipt. This reviewer is unblinded and also implements the harness; it is not independent maintainer approval. Code correction reviewers upstream did not review this fixture lesson. Both arms fork the same reviewed template, and the document arm receives a readable projection plus the exact proposal/acceptance/retirement history and source references. Retain review history; source inspection is not approval.

The helper and current requirements are identical across matched arms. The task prompt contains the feature request and points to requirements, not a lesson-specific fix. Project instructions in both arms explicitly require consulting applicable guidance before edits, distinguishing accepted/pending/historical content, checking changed sources and respecting review authority. Only the retrieval mechanism differs: Mason tools or readable project notes/review receipts. Both prohibit inventing approval and editing receipts. Current tasks authorize their requested code edits; no additional confirmation gate applies. No new lesson is required when the existing guidance remains applicable.

Each task starts a fresh disposable checkout/session. Only operation.mjs is editable for relevant tasks; greeting.txt is editable for the control. The agent may inspect the source and public smoke check. Reference implementations and the private checker remain outside the fixture. The managed helper is protected; its exported call counter verifies delegation without prescribing source syntax. A valid alternative may call the helper through another wrapper. Private checks import the submitted function in a separate Node process with a timeout; this is ordinary generated-code testing, not a hostile-code sandbox.

## Grading and evidence

Before live sessions, all eight deterministic reference cells must pass. Reject deliberate once-only cleanup and cancellation-swallowing mutations; accept explicit cleanup and managed-disposal alternatives. Negative grading tests must reject changed approval history, helper/checker changes, incorrect delegation and unrelated edits. Grade mechanically: complete session, unchanged HEAD/protected files, correct private behavior/delegation and preserved operative knowledge/review history. Allow only source-inspection metadata witnessed through the real MCP review result. Notes receipts are immutable. Do not turn retrieval timing into a hidden correctness requirement.

Separately inspect transcripts for applicable guidance before edits, pending/current/retired interpretation, unnecessary maintenance or confirmation, repeated bodies and whether MCP or hooks supplied knowledge. Timing unknown remains unknown; correct patches do not prove causal benefit. Hook/MCP observers record operation-byte witnesses and forward outputs unchanged. Notes use silent harness tool observations with the same byte witnesses, without Mason context or audit behavior. Record instrumentation and condition differences rather than presenting elapsed time as pure product latency.

Freeze binaries, helpers, fixture/observer/runner sources, tasks and this protocol before live calls. Record hashes and runtime/host identities; abort a batch if fingerprints change. Preserve failures and interrupted attempts separately; no automatic retries or retrospective grade tuning. Public upstream source receipts are pinned; no original production logs or private repository data are included.

Use configured default model/effort, $1/session cap and 180-second timeout; maximum configured host spend $8.
