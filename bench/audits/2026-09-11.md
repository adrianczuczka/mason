## Findings and implications

- **A real Mason defect:** the first ripgrep run aborted on `HomebrewFormula -> pkg/brew`. Module discovery considered this alias even though Git's source inventory contained no paths beneath it. Discovery now excludes such aliases while still refusing links used by selected source paths. A regression covers both cases. The failed run is retained in the results rather than counted as clean.
- **Directory omissions need judgment:** Click's `examples/` and `tests/`, and Cobra's `doc/`, are absent from the discovered README text. Inspection found user-facing product and usage documentation, not an asserted complete repository inventory. These three observations do not establish missing documentation that ought to be repaired. Prefer explicit repository-structure claims or agent instructions when considering stronger default signals; validate that policy on a larger labeled set first.
- **Manifest recency is mostly a review prompt:** the other 20 advisories report manifest changes after a document commit. Release-version churn remains visible in Python and Rust, and package release commits in ElevenLabs. These counts do not establish 20 stale documents. Existing release-metadata filtering is narrow; broadening it requires checking actual manifest diffs, not suppressing commit titles containing "release".
- **Discovery is not documentation coverage:** Click and Cobra each expose only their README through this discovery convention. Other Markdown filenames, Click's reStructuredText documentation, external documentation sites, snippet semantics, and example behavior were not validated. No passive finding replaced the separate investigation of ElevenLabs' examples.

The immediate product response is to let an authorized assessment close an advisory against its inspected scope, retain its evidence, and reopen it when relevant inputs change. This reduces repeated warnings without asserting that a heuristic observation was a defect. Do not infer a false-positive rate, improved agent performance, or a time-saving claim from this sample.

## Repeating the check

Use the repository URLs and exact revisions above. For a fresh target, initialize a temporary checkout, fetch the selected revision with the intended history depth, and check it out detached. From a built Mason checkout, run:

```sh
node dist/mason-audit.js --dir /absolute/path/to/target --json
```

Record the Mason source revision and local changes, target revision and shallow-history state, full JSON, stderr and exit status. Compare tracked status before and after. Increasing history depth can change historical evidence. Do not execute repository scripts to reproduce this passive check.
